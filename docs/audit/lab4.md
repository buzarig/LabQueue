# Аудит лаби 4

Чернетку складає ШІ як аналіз (`standards/ai-workflow.md`, «Роль ШІ»);
висновки погоджує автор. Таблиця критеріїв і докази навмисних порушень CI
(критерій 13) додаються перед здачею; нижче — журнал знахідок у порядку, в
якому вони трапились.

## Журнал знахідок розгортання

### З1. Перший деплой старого `main` — без Dockerfile

- **Що:** підключений до `main` сервіс Railway одразу зібрав `9444816` (лаба
  2) автоматичним Railpack і впав на «Build image»
  ([020](../../ai/lab4/020-skrinshot-railpack-failed.md)).
- **Висновок:** очікувано, до БД цей деплой не дійшов. Після PR #4 збірка йде
  з `Dockerfile` (ADR-0043).

### З2. PostgreSQL 18 замість 17

- **Що:** стандартна БД Railway — PostgreSQL 18.7
  ([022](../../ai/lab4/022-server-version-18.md)), а критерій 4 і ADR-0033
  вимагають 17, як у CI.
- **Як виправлено:** БД без даних замінено шаблоном `postgres-17` —
  `17.12` ([024](../../ai/lab4/024-server-version-17.md)). Змінити тег образу
  на місці не можна: тека даних 18 для 17 нечитабельна.

### З3. Активна версія з 500 на кожен запит

- **Що:** перший активний деплой `35b361f` повертав правильний `/version` і
  `/ready` 200, але `GET /sessions` — 500 навіть для невідомого користувача.
  У сервісі не задали Pre-deploy Command і `SEED_ON_START`
  ([029](../../ai/lab4/029-zabuv-seed-predeploy-ready-v-pr2.md)) — у БД не
  було схеми.
- **Чому blue-green не захистив:** `/ready` перевіряв лише `select 1`.
  Відтворено локально: БД без міграцій — `/ready` 200, `/sessions` 500.
- **Як виправлено:** налаштування доповнено (Redeploy); `/ready` тепер 503,
  доки не застосовано всі структурні міграції (`3ed5ed3`, ADR-0045,
  «Уточнення», `tests/db/ready-schema.test.js`).

### З4. Злиття в `main` не запускають деплой

- **Що:** після злиття PR #4 (`35b361f`), PR #5 (`a36005b`) і PR #6
  (`fefb513`) CI на `main` зелений за ~35 с, але Railway не створив жодного
  деплою — навіть у стані «Waiting for CI»
  ([033](../../ai/lab4/033-skrinshot-deployments.md),
  [034](../../ai/lab4/034-ne-zyavyvsia-deploi.md),
  [039](../../ai/lab4/039-ne-bachu-waiting.md)).
- **Перша гіпотеза — хибна.** На кожному коміті `main` до PR #6 були набори
  перевірок застосунків **Render** і **Cursor** (`queued`, 0 запусків, в
  інтерфейсі GitHub не видно — лише `commits/<sha>/check-suites`). Я
  припустив, що «Wait for CI» чекає на них. Автор прибрав обидва застосунки
  ([036](../../ai/lab4/036-vydalyv.md)): на `fefb513` лишився тільки GitHub
  Actions, але деплою однаково не було.
- **Справжня причина:** у Settings → Source сервісу — «Auto deploy
  unavailable» і «Could not load branches»: GitHub-застосунок Railway не мав
  доступу до репозиторію ([040](../../ai/lab4/040-skrinshot-auto-deploy-unavailable.md)).
  Без нього Railway не отримує подій push, тож автодеплою не було з самого
  початку. Деплої `35b361f` в історії запустили зміни налаштувань і
  Redeploy, а не злиття.
- **Як виправлено:** автор надав Railway доступ до `LabQueue` і увімкнув
  автодеплой ([041](../../ai/lab4/041-pidkliuchyv-auto-deploy.md)).
  Доказ — злиття PR #7 (sf-2): деплой після зеленого CI.
- **Висновок для перевірки:** «зелений деплой» у панелі не доводить CD.
  Доказ автодеплою — новий коміт у `main`, після якого без жодних дій у
  панелі `/version` повертає його sha.

## Кандидати «зрізаних кутів» ШІ

1. **`SHOW server_version` без `psql`.** Я дав SQL-команду, не сказавши, що
   її виконують у `psql`; автор запустив її в bash
   ([021](../../ai/lab4/021-show-server-version-ne-pratsiuie.md)).
2. **Злиття без перевірки наборів перевірок коміту.** Перед злиттям PR #4 я
   перевірив лише `gh pr checks`, який показує тільки набори з запусками, і
   не подивився `check-suites` — завислі Render і Cursor знайшлись лише
   після двох злиттів без автодеплою.
3. **Затримку пояснено без перевірки.** Деплой PR #4 з'явився через ~14 хв
   після злиття; я пояснив це повільною реакцією Railway на CI, не
   з'ясувавши, чим насправді його запущено (З4).
4. **Висновок про причину без перевірки налаштувань.** У З4 я спершу
   звинуватив Render і Cursor за повідомленнями спільноти, хоча
   найпростішу причину — чи підключено автодеплой у Settings → Source —
   можна було перевірити першою. Через це знадобився зайвий PR #6.
