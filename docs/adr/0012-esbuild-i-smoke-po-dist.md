# ADR-0012: Збірка esbuild у dist/ і smoke-тест по зібраному артефакту

- Статус: запропоновано
- Дата: 2026-09-30
- Промпт: ai/lab1/010-adr-stack.md

## Контекст і проблема

Курс вимагає «збірку» в hook-у. JavaScript-коду компіляція не потрібна, тож
треба вирішити:
- що саме означає збірка для LabQueue;
- як зробити, щоб вона щось доводила, а не була формальністю.

## Чинники рішення

- **Збірка ловить помилки**, яких не ловлять лінт і типи: зламаний
  відносний імпорт, відсутній файл.
- **Smoke-тест перевіряє** те, що реально запускатиметься.
- **Швидкість**: збірка входить у `make check` на кожному пуші.
- **Механізм вшивання sha** для `/version`
  ([ADR-0019](0019-dzherelo-sha-dlia-version.md)).

## Розглянуті варіанти

1. **esbuild:**
   - бандл `src/main.js` → `dist/`;
   - smoke-тест запускає саме `dist/`;
   - у збірку також входить `tsc`-перевірка (CHK-03).
2. **Без бандла:**
   - «збірка» — це лише `tsc --noEmit`;
   - smoke-тест запускає `src/`.
3. **Rollup або tsup**: бандл з іншим інструментом.

## Рішення

Обрано **esbuild**.
- **Що збирається:** `src/main.js` бандлиться в `dist/` для платформи
  `node`, формат ESM.
- **npm-пакети** лишаються зовнішніми (`packages: 'external'`). У бандл входить
  лише власний код, а пакети `dist/` бере з `node_modules`.
- **Smoke-тест (CHK-06)** стартує `dist/` на вільному порту й перевіряє
  `/health` і `/version`.

Навіщо пакети зовнішні:
- бандлинг пакетів ламає ті, що підвантажують файли або worker-и під час
  виконання (наприклад, transport логера pino у Fastify);
- користі для прототипу без деплою він не дає.

### Наслідки

- **Добре:**
  - зламаний відносний імпорт чи відсутній власний файл валить збірку ще до smoke;
  - smoke перевіряє артефакт, а не джерело;
  - esbuild збирає за частки секунди;
  - `define` дає вшити sha під час збірки.
- **Погано / ціна:**
  - ще одна залежність;
  - `dist/` не самодостатній: для запуску потрібен `node_modules`. Для
    лаби 1, де деплою немає, це прийнятно;
  - збірка не ловить пакет, який помилково лежить у `devDependencies`, бо
    локально він установлений. Це лишається на аудит залежностей
    ([dependencies.md](../../standards/dependencies.md));
  - `dist/` у `.gitignore`, тож `make check` пише файли поза git
    (прийнято в 007).

## Плюси й мінуси варіантів

### Без бандла

- Плюс: найпростіше, нуль залежностей.
- Мінус: «збірка» тоді лише дублює CHK-03 і нічого нового не доводить. Smoke
  перевіряє джерело, а не артефакт. Курс вимагає, щоб збірка була
  перевіркою → відкинуто.

### Rollup / tsup

- Плюс: зрілі, багато плагінів.
- Мінус: Rollup повільніший і потребує плагінів навіть для базового Node-бандла.
  tsup — обгортка над esbuild, тобто ще один шар без потреби → відкинуто.
