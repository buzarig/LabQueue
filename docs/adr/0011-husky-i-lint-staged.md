# ADR-0011: Git-hooks — husky і lint-staged

- Статус: прийнято
- Дата: 2026-09-30
- Промпт: ai/lab1/010-adr-stack.md

## Контекст і проблема

Вимоги до hook-ів:
- **К6:** hook-и встановлюються автоматично разом із залежностями;
- **К7:** брудний коміт і зламаний пуш реально блокуються.

Етапи визначено в [checks.md](../../standards/checks.md):
- **pre-commit** — формат і лінт staged-файлів;
- **commit-msg** — CHK-07 і CHK-08;
- **pre-push** — `make check`.

## Чинники рішення

- **Автоматичне встановлення** після `npm ci` без ручних кроків.
- **Перевірка лише staged-файлів** на pre-commit, щоб коміт був швидким, а
  незакомічені зміни не заважали.
- **Hook-и в git**, а не в локальних налаштуваннях розробника.

## Розглянуті варіанти

1. **husky + lint-staged.**
2. **lefthook** — один інструмент, вміє запускати команди лише для staged-файлів.
3. **Власні скрипти** в `.githooks/` + `git config core.hooksPath` у
   `prepare`.
4. **simple-git-hooks** + lint-staged.

## Рішення

Обрано **husky + lint-staged**.
- **husky:** підключається скриптом `prepare` під час `npm ci`, hook-и лежать у
  `.husky/`.
- **lint-staged:** запускає Prettier і ESLint лише для staged-файлів.

### Наслідки

- **Добре:**
  - встановлення повністю автоматичне (К6);
  - hook-и — звичайні shell-файли під git, їх видно на рев'ю;
  - lint-staged коректно працює з частково staged-файлами.
- **Погано / ціна:**
  - дві залежності заради того, що git уміє сам через `core.hooksPath`;
  - будь-який hook можна обійти через `--no-verify`, тому справжній бар'єр —
    CI ([ADR-0015](0015-github-actions.md)).

## Плюси й мінуси варіантів

### lefthook

- Плюс: один інструмент замість двох, швидкий, конфігурація в YAML.
- Мінус 1: встановлює бінарник під платформу через npm, і на частині машин
  це буває крихким.
- Мінус 2: частково staged-файли він обробляє простіше, ніж lint-staged.

Реальна альтернатива, відкинута з невеликим відривом. Кандидат, якщо аудит
залежностей захоче скоротити їх кількість.

### Власні скрипти й `core.hooksPath`

- Плюс: нуль залежностей для самих hook-ів.
- Мінус: логіку «перевірити лише staged-файли» довелося б писати й
  тестувати самим, а це найкрихкіша частина → відкинуто.

### simple-git-hooks

- Плюс: мінімалістичний.
- Мінус: hook-и описуються в `package.json` одним рядком, і складніший
  commit-msg-скрипт туди не вміщається. Відмінності від husky для нас
  несуттєві → відкинуто.
