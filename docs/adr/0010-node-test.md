# ADR-0010: Тести на вбудованому node:test

- Статус: прийнято
- Дата: 2026-09-30
- Промпт: ai/lab1/010-adr-stack.md

## Контекст і проблема

У лабі 1 потрібен smoke-тест зібраного застосунку (К8, CHK-06). З лаби 2
знадобляться юніт-тести інваріантів I1–I11. Треба обрати тестовий раннер.

## Чинники рішення

- **Мінімум залежностей**: кожна проходить аудит.
- **Нативний ESM** без трансформацій.
- **Проста інтеграція** з `make check` і CI через код виходу.
- **Достатність** для доменних тестів: assert, моки, таймери.

## Розглянуті варіанти

1. **`node:test` + `node:assert`**: вбудовані в Node 24.
2. **Vitest.**
3. **Jest.**
4. **Mocha + Chai.**

## Рішення

Обрано **`node:test`**. Тести запускає `node --test`. Smoke-тест піднімає
зібраний `dist/` і перевіряє відповіді `/health` та `/version`.

### Наслідки

- **Добре:**
  - нуль залежностей;
  - ESM працює без налаштувань;
  - є моки (`mock.fn`, `mock.timers` — знадобляться для орієнтовного часу
    S11) і coverage;
  - версія тестового раннера завжди збігається з версією Node.
- **Погано / ціна:**
  - режим спостереження (watch) бідніший, а вивід помилок менш виразний, ніж
    у Vitest чи Jest;
  - немає snapshot-тестів у звичному вигляді. Для доменної логіки черги вони
    не потрібні.

## Плюси й мінуси варіантів

### Vitest

- Плюс: швидкий, зручний вивід, сумісний із Jest API.
- Мінус: окрема залежність із власним деревом пакетів (Vite). Усе, що він
  дає понад `node:test`, — це зручність розробки, а не потреба LabQueue →
  відкинуто.

### Jest

- Плюс: найвідоміший.
- Мінус: підтримка ESM досі потребує експериментальних прапорців або
  трансформацій. Важке дерево залежностей → відкинуто.

### Mocha + Chai

- Плюс: зрілі, гнучкі.
- Мінус: два пакети замість нуля. Нічого суттєвого понад `node:test` для
  LabQueue не дають → відкинуто.
