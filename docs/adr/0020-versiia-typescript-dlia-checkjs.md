# ADR-0020: Версія TypeScript для перевірки типів — 7.0.x

- Статус: прийнято
- Дата: 2026-09-30
- Промпт: ai/lab1/013-pipeline-review.md

## Контекст і проблема

[ADR-0007](0007-javascript-esm-jsdoc-checkjs.md) обрав JavaScript + JSDoc +
`tsc --noEmit --checkJs` (strict), але версію TypeScript не зафіксував. Під
час реалізації конвеєра (промпт 012) ШІ встановив `typescript` без явної
версії, і npm узяв поточний `latest` — **7.0.2**. Автор дізнався про це
лише після коміту.

TypeScript 7 — нова нативна реалізація компілятора. Підтримку JavaScript і
JSDoc у ній переписано, тож треба перевірити, чи checkJs працює для наших
конструкцій, і свідомо зафіксувати версію.

Це уточнення до ADR-0007: рішення «checkJs замість TypeScript» не
змінюється, тому ADR-0007 не замінюється.

## Чинники рішення

- **Повнота перевірки JSDoc-конструкцій**, які ми використовуємо й
  плануємо (див. таблицю нижче).
- **Підтримка версії** на весь курс.
- **Відтворюваність.** Мінорне оновлення компілятора не повинно
  непомітно змінити результат CHK-03.
- **Швидкість**, бо CHK-03 входить у pre-push і CI.

## Розглянуті варіанти

1. **TypeScript 7.0.x** — поточний `latest` з 2026-07-08, нативна реалізація.
2. **TypeScript 6.0.x** — остання версія на JavaScript-реалізації, перехідна
   до 7.
3. **TypeScript 5.9.x** — попередня зріла гілка.

## Перевірка варіантів

Проба (промпт 013) — файл із 8 навмисними помилками, по одній на кожну
конструкцію. Налаштування ті самі, що в `tsconfig.json`: strict, nodenext,
`@types/node@24`.

| # | Конструкція | 5.9.3 | 6.0.3 | 7.0.2 |
|---|---|---|---|---|
| 1 | `@typedef` з union рядкових літералів (статуси черги) | ✔ | ✔ | ✔ |
| 2 | необов'язкове поле → `number` під strict | ✔ | ✔ | ✔ |
| 3 | `@template` (generic) | ✔ | ✔ | ✔ |
| 4 | `@callback` | ✔ | ✔ | ✔ |
| 5 | `NodeJS.ProcessEnv` (`@types/node`) | ✔ | ✔ | ✔ |
| 6 | JSDoc-каст `/** @type {T} */ (x)` | ✔ | ✔ | ✔ |
| 7 | тип через `import("node:http")` | ✔ | ✔ | ✔ |
| 8 | типи API `node:fs` | ✔ | ✔ | ✔ |

✔ — помилку знайдено в очікуваному рядку. Хибних помилок не було в жодній
версії.

Додатково у 7.0.2:
- **Тип із пакета в `.cjs`.** `import('dependency-cruiser').IConfiguration`
  у `.dependency-cruiser.cjs` ловить недопустиме значення поля.
- **Поточний код.** Увесь код репозиторію проходить без помилок.

## Рішення

Обрано **TypeScript 7.0.x**.
- **Діапазон у `package.json`** — `~7.0.2`: дозволені патчі 7.0, а 7.1 і
  вище — лише через новий ADR.
- **Навіщо фіксувати мінорну версію:** нова мінорна версія компілятора може
  додати помилки, і CHK-03 почервонів би без змін у коді.

### Наслідки

- **Добре:**
  - для наших конструкцій перевірка така сама, як у 5.9 і 6.0;
  - це поточна стабільна гілка, тож підтримки вистачить на курс;
  - нативна реалізація швидша — за даними розробників TypeScript. На нашому
    обсязі коду різницю не вимірювали;
  - версія тепер свідома й записана.
- **Погано / ціна:**
  - гілка 7 молода: у реліз вона вийшла за три місяці до цього рішення;
  - JSDoc-конструкції, яких немає в пробі (`@enum`, `@class` на функціях,
    Closure-синтаксис типів), не перевірені й можуть поводитися інакше, ніж
    у 5.x. Правило: нову JSDoc-конструкцію спершу перевіряємо, чи ловить
    CHK-03 помилку в ній;
  - частина інструментів екосистеми ще орієнтується на 5.x. Зараз
    TypeScript у нас використовує лише `tsc`, dependency-cruiser працює
    без нього (`tsPreCompilationDeps: false`).

## Плюси й мінуси варіантів

### TypeScript 6.0.x

- Плюс: остання JavaScript-реалізація, максимально сумісна з 5.x за
  поведінкою.
- Мінус: перехідна гілка — її мета підготувати до 7. Для наших конструкцій
  результат ідентичний, тож залишатися на ній означало б запланувати ще
  одну міграцію → відкинуто.

### TypeScript 5.9.x

- Плюс: найзріліша, найбільше досвіду в екосистемі.
- Мінус: на два покоління старша, а для наших конструкцій перевага нуль.
  Повільніша на кожному pre-push → відкинуто.
