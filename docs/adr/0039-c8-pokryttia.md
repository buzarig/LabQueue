# ADR-0039: Покриття через c8 — звіт по `src/`, поріг для `transitions.js`

- Статус: прийнято
- Дата: 2026-11-18
- Промпт: ai/lab3/003-vidpovidi-pro-testy.md, ai/lab3/004-vidpovidi-transitions-make-test.md, ai/lab3/012-tak-adr-instrumenty.md, ai/lab3/013-pohodzhuiu-variant-a.md

## Контекст і проблема

Курс вимагає «розумного покриття критичної логіки — гілки, не лише
рядки». Spec лаби 3 (критерії 11, 12) задає звіт покриття для `src/`, ціль
у 100 % гілок для `transitions.js` і мінімум 80 %, нижче якого падає
`make test`. Тести йдуть двома раннерами: `node:test` і Vitest
([ADR-0038](0038-vitest-dlia-transitions.md)).

## Чинники рішення

- **Один інструмент для обох раннерів**: обидва працюють на V8, отже
  покриття можна брати з `NODE_V8_COVERAGE`.
- **Поріг лише для `transitions.js`** (рішення автора, промпт 004): старий
  код поза лабою 3 не повинен валити `make test`.
- **Поріг перевіряє unit-рівень**: `transitions.js` проходять і сценарні
  тести, але 100 % гілок мають дати саме Vitest-тести модуля (критерій 4).

## Розглянуті варіанти

1. **c8** — обгортка над `NODE_V8_COVERAGE` для будь-якої команди Node.
2. **`node --test --experimental-test-coverage`** і окремо
   `@vitest/coverage-v8`.
3. **nyc (Istanbul)** з інструментуванням коду.

## Рішення

Обрано **варіант 1** (рішення автора, промпт 004).

- Пакет `c8`, основна версія **12** (`^12.0.0`).
- **Два прогони:**
  - _поріг_: `c8 --include src/modules/queue/transitions.js --check-coverage
--branches 80 --functions 80` навколо Vitest. Нижче будь-якого з двох
    порогів — код виходу 1 і падіння `make test`. Ціль для обох — 100 %;
  - _звіт_: `c8 --include "src/**"` навколо unit- та інтеграційних тестів
    на `node:test` (in-process: `tests/unit`, `tests/scenarios` на memory і
    pg, `tests/db`). E2E запускає зібраний `dist/` окремим процесом, і в цей
    звіт не потрапляє.
- Звіти — у `reports/lab3/` (текст), робочі файли c8 — у `coverage/`
  (уже в `.gitignore`).

### Наслідки

- **Добре:**
  - один інструмент і один формат звіту для двох раннерів;
  - поріг міряє саме unit-тести модуля, а не випадкове покриття сценаріями.
- **Погано / ціна:**
  - V8 рахує гілки лише всередині викликаних функцій: функція, яку жоден
    тест не викликав, не додає непокритих гілок. На пробі з двома викликами
    вийшло 75 % гілок при 29 % функцій. Тому поріг гілок доповнено порогом
    функцій (варіант «а», промпт 013) — це на один поріг більше, ніж у
    критерії 12 spec, і потребує sf-пункту;
  - c8 бачить Vitest лише з пулом `threads`;
  - нова залежність із транзитивними знахідками `npm audit` (`glob`,
    `test-exclude`), лише в devDependencies.

## Плюси й мінуси варіантів

### Варіант 2: вбудоване покриття кожного раннера

- Плюс: без c8 для `node:test`.
- Мінус: два формати, два способи задати поріг, а прапорець Node досі
  експериментальний → відкинуто.

### Варіант 3: nyc

- Плюс: точний підрахунок гілок через інструментування.
- Мінус: інструментування ESM вимагає завантажувача, Vitest має свій
  трансформ — конфлікт двох перетворень коду → відкинуто.
