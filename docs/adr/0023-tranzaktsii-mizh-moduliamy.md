# ADR-0023: Транзакції між модулями — явний `tx` в API модулів

- Статус: прийнято
- Дата: 2026-10-22
- Промпт: ai/lab2/015-adr-pyshemo-zaraz.md

## Контекст і проблема

Команда часто зачіпає кілька модулів:
- S4: `queue` переводить записи в `missed`, `sessions` — заняття у
  `finished`;
- S10: `queue` читає стан і ліміт заняття з `sessions` і пише запис;
- кожен POST: ключ ідемпотентності ([ADR-0024](0024-idempotency-key.md)).

Усе це має бути однією транзакцією (spec лаби 2, К8). Водночас модулі не
знають, PostgreSQL під ними чи пам'ять, і не імпортують `platform`
(правила 4–5 лаби 1).

## Чинники рішення

- **Атомарність** команди, що зачіпає кілька модулів.
- **Межі модулів**: домен не знає сховища, `main.js` дає залежності.
- **Однаковість** для двох адаптерів ([ADR-0027](0027-statyka-yak-druhyi-adapter.md)).
- **Видимість**: на рев'ю видно, які виклики в якій транзакції.

## Розглянуті варіанти

1. **Явний `tx`.** `main.js` дає модулям функцію `transaction(fn)`; `fn`
   отримує `tx`, і кожна функція API модуля, що читає чи пише, приймає `tx`
   першим аргументом.
2. **Неявний контекст** через `AsyncLocalStorage`: репозиторії самі беруть
   поточну транзакцію.
3. **Транзакція на модуль** і компенсація при збої (сага).

## Рішення

Обрано **варіант 1**.
- **Хто відкриває:** обробник маршруту модуля, що веде сценарій. Для POST —
  обгортка ідемпотентності, яка далі викликає обробник з тим самим `tx`.
- **Що таке `tx`:** для PostgreSQL — клієнт пулу всередині `begin … commit`;
  для пам'яті — доступ до стану під м'ютексом зі знімком для відкату.
- **Блокування** за викладачем береться через `tx.lockTeacher(id)`
  ([ADR-0022](0022-advisory-lock-za-vykladachem.md)).

### Наслідки

- **Добре:**
  - у сигнатурі видно, що функція працює в транзакції, і її не викличеш
    поза нею;
  - тести підставляють свою реалізацію `transaction`, наприклад зі збоями
    (К11);
  - S4 — одна транзакція без хитрощів.
- **Погано / ціна:**
  - `tx` проходить крізь усі шари, сигнатури довші;
  - модуль може забути передати `tx` і відкрити ще одну транзакцію. Захист —
    API модулів приймає лише `tx`, без доступу до пулу.

## Плюси й мінуси варіантів

### Варіант 2: `AsyncLocalStorage`

- Плюс: сигнатури чисті.
- Мінус: залежність від транзакції неявна. Виклик поза контекстом тихо
  йде повз транзакцію, і цього не видно ні в коді, ні на рев'ю → відкинуто.

### Варіант 3: сага

- Плюс: модулі повністю незалежні, підходить для окремих БД.
- Мінус: між компенсаціями інваріанти I1–I10 тимчасово порушені, а БД у нас
  одна, тож звичайна транзакція дешевша й надійніша → відкинуто.
