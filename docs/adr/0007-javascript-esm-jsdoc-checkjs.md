# ADR-0007: JavaScript (ESM) з JSDoc-типами і tsc --checkJs

- Статус: запропоновано
- Дата: 2026-09-30
- Промпт: ai/lab1/010-adr-stack.md

## Контекст і проблема

Курс — з Node.js. Потрібна статична перевірка типів: доменні інваріанти
(статуси, бал 0–100, ролі) краще ловити до запуску. Водночас треба вирішити,
чи писати на TypeScript, і яка система модулів.

## Чинники рішення

- **Статичний аналіз у `make check`** (CHK-03), який валить зламаний тип.
- **Код, що виконується, збігається з написаним**: без перетворень між
  джерелом і запуском, крім бандла ([ADR-0012](0012-esbuild-i-smoke-po-dist.md)).
- **Фокус курсу** — Node.js і JavaScript.
- **Мінімум обмежень синтаксису** й конфігурації.

## Розглянуті варіанти

1. **JavaScript ESM + JSDoc-типи + `tsc --noEmit --checkJs` (strict).**
2. **TypeScript зі стиранням типів у Node 24** (type stripping).
   - `.ts` запускається напряму, `tsc --noEmit` лише перевіряє.
   - Дозволений лише синтаксис, який можна стерти.
3. **TypeScript зі збіркою** (`tsc` у JavaScript або через esbuild).
4. **JavaScript без статичної перевірки типів**: лише ESLint.

## Рішення

Обрано **варіант 1**.
- **Код:** JavaScript з `"type": "module"`.
- **Типи:** описуються JSDoc (`@typedef`, `@param`, `@returns`).
- **Перевірка:** `tsc --noEmit --checkJs --strict` у `make check` (CHK-03).
  Ця перевірка й робить `typescript` залежністю розробки.

### Наслідки

- **Добре:**
  - те, що написано, те й виконується;
  - strict-перевірка ловить ті самі помилки, що й TypeScript;
  - жодних обмежень синтаксису;
  - код лишається JavaScript, а курс саме про нього.
- **Погано / ціна:**
  - JSDoc-типи багатослівніші за TypeScript. Складні типи (union статусів,
    generic-и) виглядають громіздко;
  - частину помилок checkJs показує менш зрозуміло, ніж TypeScript;
  - `typescript` усе одно в `devDependencies`.

## Плюси й мінуси варіантів

### TypeScript зі стиранням типів

- **Плюс:** чистіший синтаксис типів. Node 24 запускає `.ts` без кроку збірки,
  тож головний аргумент «TypeScript вимагає збірки» тут майже зникає.
- **Мінус 1:** синтаксис обмежений тим, що можна стерти. `enum`,
  `namespace` і параметри-властивості заборонені, а це саме те, що
  першим хочеться для статусів черги.
- **Мінус 2:** імпорти мають містити `.ts`, і для цього потрібні окремі
  налаштування tsc, ESLint і esbuild.
- **Мінус 3:** мова змістилася б від Node.js/JavaScript, на які розрахований
  курс.
- **Висновок:** реальна альтернатива. Відкинуто через фокус курсу й
  обмеження синтаксису, а не через «потрібна збірка».

### TypeScript зі збіркою

- Плюс: повний TypeScript без обмежень.
- Мінус: між написаним і виконуваним з'являється трансляція, source maps
  тощо. Крок збірки стає обов'язковим навіть для запуску тестів. Для каркаса
  це зайвий шар → відкинуто.

### Без статичної перевірки

- Плюс: нуль конфігурації.
- Мінус: помилки типів (`score` як рядок, опечатка в статусі) спливають лише
  під час виконання. Курс вимагає статичний аналіз → відкинуто.
