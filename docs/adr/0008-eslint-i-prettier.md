# ADR-0008: Якість коду — ESLint (flat config) і Prettier

- Статус: запропоновано
- Дата: 2026-09-30
- Промпт: ai/lab1/010-adr-stack.md

## Контекст і проблема

Курс вимагає стиль коду, форматер і лінтер. Hook має реально блокувати
брудний коміт (К7). Треба обрати інструменти:
- **форматування** — як виглядає код;
- **лінтингу** — підозрілі конструкції: невикористані змінні, забутий `await`
  тощо.

## Чинники рішення

- **Автоматичне виправлення** формату, щоб стиль не був предметом рев'ю.
- **Правила для Node.js/ESM** і сумісність із JSDoc/checkJs.
- **Підтримка lint-staged** для перевірки лише staged-файлів
  ([ADR-0011](0011-husky-i-lint-staged.md)).
- **Поширеність**: рев'юер знає інструменти без пояснень.

## Розглянуті варіанти

1. **ESLint (flat config) + Prettier**, ролі розділені. Prettier відповідає
   за формат, ESLint — за логіку. Правила ESLint, що конфліктують із
   Prettier, вимкнені.
2. **Biome** — один інструмент і для формату, і для лінту.
3. **Лише ESLint** зі стилістичними правилами (`@stylistic`) замість
   Prettier.

## Рішення

Обрано **варіант 1**.
- **ESLint 9+:** flat config `eslint.config.js` з рекомендованими правилами для
  JavaScript і Node.js.
- **Prettier:** з мінімальною конфігурацією.
- **Де запускаються:** обидва — у pre-commit через lint-staged (CHK-01,
  CHK-02) і в `make check`.

### Наслідки

- **Добре:**
  - чіткий розподіл ролей;
  - Prettier знімає всі суперечки про стиль;
  - екосистема плагінів ESLint знадобиться, якщо правил стане більше;
  - обидва інструменти знає будь-який рев'юер.
- **Погано / ціна:**
  - дві залежності й дві конфігурації;
  - ESLint разом із плагінами — одна з найважчих груп пакетів у
    `devDependencies`;
  - на великих проєктах ESLint повільніший за Biome. На LabQueue цього не
    видно.

## Плюси й мінуси варіантів

### Biome

- Плюс: один швидкий інструмент, одна конфігурація, одна залежність.
- Мінус: набір правил лінту вужчий, ніж в ESLint. Немає плагінів для
  майбутніх потреб, наприклад правил імпортів. Менш знайомий рев'юерам, тож
  на захисті знадобиться окреме пояснення → відкинуто. Кандидат на перегляд,
  якщо аудит залежностей покаже, що ESLint зайвий.

### Лише ESLint зі стилістичними правилами

- Плюс: на одну залежність менше.
- Мінус: стилістичні правила ESLint форматують неповно (довгі рядки,
  перенос аргументів). Стиль знову стає предметом ручних правок і рев'ю →
  відкинуто.
