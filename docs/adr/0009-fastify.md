# ADR-0009: HTTP-фреймворк Fastify

- Статус: запропоновано
- Дата: 2026-09-30
- Промпт: ai/lab1/010-adr-stack.md

## Контекст і проблема

Застосунку потрібен HTTP-сервер:
- у лабі 1 — `GET /health` і `GET /version` (К8);
- з лаби 2 — API сценаріїв S1–S13.

Модулі мають реєструвати свої маршрути самі, не бачачи внутрішніх частин
один одного ([architecture.md](../specs/lab1-foundation/architecture.md),
«Модулі»).

## Чинники рішення

- **Межі модулів у маршрутах**: кожен модуль — окремий ізольований плагін.
- **Валідація вхідних даних** без окремої бібліотеки: бал 0–100, id, статуси.
- **Структурований логер** без окремої залежності.
- **Мало коду на старті** й зрозумілість на захисті.

## Розглянуті варіанти

1. **Fastify.**
2. **Express.**
3. **Вбудований `node:http`** без фреймворку.
4. **Hono.**

## Рішення

Обрано **Fastify**.
- **Плагіни.** Кожен доменний модуль експортує з `index.js` Fastify-плагін.
  `main.js` реєструє їх, а інкапсуляція плагінів не дає модулям бачити
  декоратори й хуки один одного.
- **Валідація.** Вхідні дані перевіряються JSON-схемами маршрутів.
- **Логер** — вбудований pino.

### Наслідки

- **Добре:**
  - інкапсуляція плагінів повторює межі модулів;
  - JSON-схеми дають валідацію й серіалізацію без додаткових пакетів;
  - `inject()` дозволяє тестувати маршрути без мережі.
- **Погано / ціна:**
  - Fastify має більше власних понять (плагіни, декоратори, `fastify-plugin`),
    ніж Express;
  - модулі залежать від Fastify напряму. Це свідомо: плагін — частина
    публічної точки входу.

## Плюси й мінуси варіантів

### Express

- Плюс: найвідоміший, найбільше прикладів.
- Мінус 1: немає інкапсуляції — middleware й маршрути глобальні, тож межі
  модулів у HTTP-шарі тримались би лише домовленістю.
- Мінус 2: немає вбудованої валідації. Знадобився б окремий пакет (zod, joi),
  тобто ще одна залежність для аудиту.

→ Відкинуто.

### Вбудований `node:http`

- Плюс: нуль залежностей.
- Мінус: маршрутизацію, розбір JSON, валідацію й обробку помилок довелося б
  писати самим. Для двох ендпоінтів лаби 1 це дешево, але для 13 сценаріїв —
  саморобний фреймворк, який теж треба тестувати → відкинуто.

### Hono

- Плюс: легкий, сучасний, валідація через адаптери.
- Мінус: орієнтований на edge-середовища, а в Node потрібен адаптер. Модель
  ізоляції модулів слабша, ніж у плагінів Fastify → відкинуто.
