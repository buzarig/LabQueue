# ADR-0019: Джерело sha для /version — вшивання під час збірки

- Статус: прийнято
- Дата: 2026-09-30
- Промпт: ai/lab1/010-adr-stack.md

## Контекст і проблема

К8 (sf-15) вимагає:
- `GET /version` → `{"sha":"<git sha>"}`;
- або `{"sha":"unknown"}`, якщо sha визначити неможливо, але без падіння.

DEFENSE вказує sha вершини гілки, на якій пройшов `make verify` (sf-7).
Треба обрати, звідки застосунок бере sha.

## Чинники рішення

- **Артефакт знає свою версію.** `dist/`, який перевіряє smoke-тест
  ([ADR-0012](0012-esbuild-i-smoke-po-dist.md)), сам знає, з якого коміту
  зібраний.
- **Без git під час виконання.** Застосунок не залежить від git і `.git` на
  машині, де працює.
- **Надійний `unknown`**: без git — `unknown`, а не падіння чи зависання.
- **Перевірюваність у smoke-тесті**: відповідь можна порівняти з
  `git rev-parse HEAD`.

## Розглянуті варіанти

1. **Вшивання під час збірки:**
   - build-скрипт виконує `git rev-parse HEAD`;
   - esbuild підставляє значення через `define`;
   - якщо git недоступний — `unknown`.
2. **`git rev-parse HEAD` під час запуску** (`child_process`) з fallback
   на `unknown`.
3. **Змінна оточення**, наприклад `GIT_SHA`, яку задає той, хто запускає
   (CI, деплой). Якщо її немає — `unknown`.

## Рішення

Рекомендовано **варіант 1**.
- **Збірка:** `dist/` отримує константу з sha.
- **Застосунок:** `/version` повертає її. Якщо константа не підставлена
  (запуск `src/` без збірки), повертає `unknown`.
- **Smoke-тест (CHK-06)** порівнює відповідь з `git rev-parse HEAD`.

### Наслідки

- **Добре:**
  - артефакт самоописний;
  - під час виконання git не потрібен і дочірніх процесів немає;
  - `unknown` визначається один раз під час збірки, тож під час роботи
    сервера падати нема чому.
- **Погано / ціна:**
  - sha відповідає `HEAD`, а не вмісту робочого дерева. Збірка з
    незакоміченими змінами покаже sha останнього коміту. Для DEFENSE це
    безпечно, бо `make verify` запускається на закоміченій вершині гілки.
    Позначку `-dirty` можна додати окремим рішенням, але К8 зараз дозволяє
    лише sha або `unknown`;
  - `dist/` після нового коміту без перезбірки показує старий sha.
    `make check` завжди перезбирає перед smoke, тож перевірка це ловить;
  - запуск `src/` напряму завжди дає `unknown`.

## Плюси й мінуси варіантів

### `git rev-parse` під час запуску

- Плюс: завжди актуальний sha, без збірки.
- Мінус: застосунок залежить від git і `.git` під час виконання та від
  робочої директорії. Дочірній процес при старті — зайва точка відмови. Sha
  описує директорію, з якої запущено, а не артефакт → відкинуто.

### Змінна оточення

- Плюс: стандартний підхід для деплою, жодної логіки в застосунку.
- Мінус: кожен запуск (локально, smoke-тест, hook) має задавати змінну.
  Інакше `unknown` навіть там, де git є, і smoke-тест не доведе, що `/version`
  повертає справжній sha. Деплою в лабі 1 немає → відкинуто для лаби 1.
  Може доповнити варіант 1, коли з'явиться деплой.
