# ADR — записи архітектурних рішень

**Навіщо.** Через місяць питання «чому так?» має відповідь у репозиторії,
а не в пам'яті. На захисті ADR показує, що рішення вибране з реальних
варіантів, а не взяте першим-ліпшим.

## Коли ADR обов'язковий

ADR потрібен, якщо виконується хоча б одна з умов:
- є **реальні альтернативи**: принаймні дві, які можна було б обрати
  без абсурду;
- рішення **дорого змінити** пізніше: формат даних, межі модулів, інструмент,
  на який спирається конвеєр.

Кожен інструмент і технологія — завжди ADR (К3).

## Розміщення й нумерація

- **Шлях:** `docs/adr/NNNN-коротка-назва.md`, наприклад
  `0003-model-pozytsii-v-cherzi.md`.
- **Нумерація** наскрізна для всіх лаб, чотири цифри, номери не
  перевикористовуються. Навіщо: посилання «ADR-0003» лишається однозначним
  через весь курс.
- **Один ADR — одне рішення.**

## Статуси

| Статус | Хто ставить | Коли |
|---|---|---|
| `запропоновано` | ШІ | чернетка в коміті ШІ |
| `прийнято` | автор | у своєму коміті «прийнято». Цей дифф і є доказом прийняття |
| `відхилено` | автор | варіант розглянуто й відкинуто. Файл лишається як історія |
| `замінено ADR-NNNN` | автор | рішення переглянуто. Новий ADR посилається на старий |

Прийнятий ADR по суті не редагується. Зміна рішення оформлюється новим ADR,
а старий отримує статус `замінено`. Навіщо: історія рішень лишається чесною.
Виправляти друкарські помилки можна.

## Шаблон (MADR, українською)

```markdown
# ADR-NNNN: Назва рішення

- Статус: запропоновано
- Дата: РРРР-ММ-ДД
- Промпт: ai/labN/NNN-….md

## Контекст і проблема

Яку проблему розв'язуємо, 2–4 речення. Посилання на критерій spec або розділ
architecture.md.

## Чинники рішення

- Що важливо для LabQueue: наприклад, перевірюваність у конвеєрі, кількість
  залежностей, вартість зміни.

## Розглянуті варіанти

1. Варіант A
2. Варіант B
3. Варіант C

## Рішення

Обрано **варіант A**, тому що … (прив'язка до чинників).

### Наслідки

- Добре: …
- Погано / ціна: …

## Плюси й мінуси варіантів

### Варіант B

- Плюс: …
- Мінус: … → чому відкинули.

### Варіант C

- …

## Посилання

- …
```

Вимоги до змісту:
- **Альтернативи.** 2–3 реальні альтернативи для кожного варіанта. Для кожної
  відкинутої записано, чому її відкинули стосовно LabQueue, а не взагалі.
- **Наслідки.** Розділ «Наслідки» містить і ціну рішення. ADR без мінусів
  вважається неповним.

## Як перевіряється

- **Наявність ADR з мінімуму К3:** `ls docs/adr/`, вручну на рев'ю.
- **Реальні альтернативи й обґрунтування:** MAN-03 у [checks.md](checks.md),
  вручну на рев'ю.
- **Статус `прийнято`:** стоїть у комітах автора. Перевіряється
  `git log -p -- docs/adr/`, вручну.
