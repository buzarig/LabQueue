# Definition of Done

**Навіщо.** Один чекліст перед відкриттям PR. Лаба здана, коли відмічені всі
пункти. Кожен пункт прив'язаний до доказу, щоб «готово» не було думкою.

Джерело кожного пункту вказане в дужках:
- **курс** — вимога курсу;
- **NNN** — домовленість автора з промпту `ai/lab1/NNN-….md`.

## Spec і рішення

- [ ] `spec.md`: що і навіщо, обсяг, критерії з однозначною перевіркою,
      ≤ 450 слів (курс; 004 → CHK-10, MAN-02).
- [ ] Критерії закомічені до коду. Коміти стандартів, архітектури й ADR
      раніше за перший коміт коду (курс; К4).
- [ ] `architecture.md` містить усі розділи з К2 (002, 003).
- [ ] Кожна зміна прийнятого тексту spec має sf-пункт і мітку `(sf-N)` (002, 003).
- [ ] ADR за MADR на кожне рішення з мінімуму К3. Усі ADR мають статус
      `прийнято` (курс; 002 → MAN-03).

## Код і конвеєр

- [ ] На свіжому клоні `make check` зелений (курс; К5).
- [ ] CI зелений на останньому коміті PR (002; К5).
- [ ] Hook-и реально блокують брудний коміт і зламаний пуш — доказ у
      `reports/lab1/` (курс; К7 → CHK-11).
- [ ] `make verify` пройшов на вершині гілки. Звіти в `reports/lab1/`
      актуальні (003; CHK-11, CHK-12).
- [ ] Кожна перевірка етапу verify з [checks.md](checks.md) має свій звіт у
      `reports/labN/`, і `verify.txt` їх перелічує. Звіряється з реєстром
      (014; розбіжність Р2 — звіт К10 був у реєстрі, але не в `make verify`).
- [ ] Кожна залежність має рядок «навіщо» в README (spec → MAN-04).

## Слід ШІ й аудит

- [ ] Кожен промпт дослівно в `ai/labN/`, кожен коміт ШІ з трейлером `Prompt:`
      (курс; 002 → CHK-07, MAN-05).
- [ ] `docs/audit/labN.md` (курс; К13) містить:
  - [ ] статус кожного критерію з доказом;
  - [ ] топ-3 розбіжності реалізації зі spec → коміт;
  - [ ] топ-3 зайві або неправильні залежності з рішенням;
  - [ ] топ-3 «зрізані кути» ШІ: промпт → фідбек → spec-fix/стандарт → коміт.

## Репозиторій і здача

- [ ] `make check` не знаходить порушень гігієни (курс; К11 → CHK-09).
- [ ] Секретів немає (курс → MAN-06).
- [ ] Реалістична історія: один логічний крок на коміт (курс; 002 → MAN-01).
- [ ] `DEFENSE.md` у корені (курс; 002 → MAN-07):
  - ≤ 1 сторінки;
  - розділи за шаблоном курсу: що і навіщо, топ-3 розбіжності → коміт,
    ключове рішення → ADR, перевірка `make verify` → результат, sha.
- [ ] Sha з DEFENSE — вершина гілки, на якій пройшов `make verify` (002).
- [ ] PR `feature-гілка → main` з коментарями. Злиття звичайним merge, не
      squash (курс; 002).

## Як перевіряється

Автор проходить чекліст перед відкриттям PR. Кожен пункт посилається на
ID у [checks.md](checks.md) або на критерій spec. Пункти без ID перевіряються
вручну на рев'ю. Сам DoD є ручною перевіркою (MAN-08).
