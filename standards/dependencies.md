# Залежності

**Навіщо.** Кожен пакет — це код, який ми не писали, але за який
відповідаємо: безпека, оновлення, розмір, час `npm ci`. Аудит курсу окремо
шукає зайві й неправильні залежності, тому правило стоїть на вході, а не
наприкінці.

## Коли можна додати залежність

Залежність додається, лише якщо виконано всі умови:

1. **Вбудованого немає.** Потребу не закриває сам Node.js (`node:test`,
   `node:http`, `node:util` тощо) або вже наявна залежність.
2. **Мета конкретна.** Є задача, яка потребує пакет саме зараз, а не
   «знадобиться потім».
3. **Є ADR, якщо є альтернативи.** Інструмент чи бібліотека з реальними
   альтернативами має ADR ([adr.md](adr.md)) до або разом із додаванням.
4. **Правильний тип.** Інструменти розробки (лінтер, форматер, збірка,
   hook-и) йдуть у `devDependencies`. У `dependencies` — лише те, що
   потрібне застосунку під час роботи.
5. **Основна версія — теж рішення.** Основна (major) версія пакета
   фіксується в ADR або ставиться питанням до коміту. Не можна брати
   `latest` мовчки. Діапазон у `package.json` відповідає ADR. Навіщо:
   TypeScript 7 потрапив у проєкт неявно, його обґрунтування довелося писати
   постфактум (ADR-0020, аудит, кандидат 5).

## Оформлення

- **Рядок «навіщо».** У README, розділ «Залежності», кожен пакет з
  `package.json` має один рядок: `пакет — навіщо`. Рядок додається в тому ж
  коміті, що й пакет.
- **Lockfile** закомічений. Встановлення лише через `npm ci`
  ([checks.md](checks.md), «Цілі make»).
- **Видалення.** Коли пакет прибирають, прибирають і рядок у README.

## Використання в аудиті

Для кожного пакета з `npm ls --depth=0` на рев'ю відповідаємо на три
питання:
1. Чи використовується він узагалі?
2. Чи не закриває цю потребу вбудований модуль Node.js?
3. Чи правильний тип (`dependencies` / `devDependencies`)?

Пакети з відповіддю «ні / так / ні» — кандидати в топ-3 зайвих або
неправильних залежностей. Для кожного записується рішення: прибрати,
перенести або лишити з обґрунтуванням.

## Як перевіряється

- **Рядок «навіщо» в README:** MAN-04 у [checks.md](checks.md), вручну на
  рев'ю. Автоматичної перевірки поки немає, це кандидат на автоматизацію.
- **ADR для інструментів:** MAN-03, вручну.
- **Встановлення через `npm ci`:** ціль `make check` (CHK-01…CHK-09
  запускаються лише після нього).
