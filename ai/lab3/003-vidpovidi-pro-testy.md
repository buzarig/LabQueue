Я думаю, краще зробити так:

Для Unit беремо машину станів запису в черзі (S5–S8), бо там більше різних сценаріїв, які можна перевірити.

Для інтеграційних тестів залишаємо те, що вже є в tests/db і tests/scenarios з STORAGE=pg. Не бачу сенсу робити ще один окремий шар, якщо ці тести вже перевіряють роботу з PostgreSQL.

Для E2E так, запускаємо зібраний dist/ окремим процесом, підключаємо реальну PostgreSQL і перевіряємо повний сценарій через HTTP.

Нехай make test запускає всі основні тести. Для бази використовуємо наш make db-up і .pgdata. Docker поки не потрібен, якщо його немає у вимогах.

Для мутаційного тестування краще взяти Stryker з Vitest, але тільки для обраного unit-модуля, щоб не ускладнювати весь проєкт. Запуск можна зробити окремою командою.

Покриття міряємо через c8. Думаю, 80% по гілках буде достатньо як мінімум, але якщо вийде більше, то ще краще.

DEFENSE робимо так само, як у другій лабораторній: docs/defense/lab3.md і оновлюємо DEFENSE.md.

Загалом я б хотів максимально використати те, що вже є в проєкті, і не додавати зайвих складнощів. Головне, щоб усі вимоги лабораторної були виконані
