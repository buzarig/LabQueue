Мета: unit + інтеграційні + E2E + мутаційне тестування.

Що зробити:
• Передумова: розумне покриття критичної логіки (гілки, не лише рядки).
• Unit-тести: достатньо одного невеликого модуля, покритого повністю (усі його випадки) — мета показати вміння, а не покрити всю програму. Інтеграційні (з підняттям залежностей: БД, HTTP-сервер), E2E.
• Одна команда (напр. make test) піднімає все потрібне (БД/Docker, міграції, сервіс) і запускає всі тести.
• Мутаційне тестування (Stryker / PIT / mutmut / cosmic-ray). Звіт: класифікувати вижилих мутантів (реальна прогалина / еквівалентний / прийнятний).
• Аудит: топ-3, де «зелені» тести не ловлять реальні баги; підсилити.

• DEFENSE.md: аналіз ефективності тестів + make mutation для відтворення.

Ознаки відмінного виконання: є всі рівні тестів; звіт мутацій із класифікацією вижилих; видно підсилення слабких тестів; прогін відтворюваний однією командою.

Здача — 2 входи:
• Посилання на GitHub PR.
• DEFENSE — заповніть прикріплений шаблон (Google Doc, копія для кожного студента) або додайте власний DEFENSE.md.

Повторна здача: той самий PR і та сама робота в Classroom; у коментарі — що змінено після рев'ю, а для незмінених зауважень — чому.
